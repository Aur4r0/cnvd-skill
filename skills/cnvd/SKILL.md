# cnvd 未授权广扫（2.3 · 2026-09-13）

> 定位：**广扫出量** —— 规则预置（AutoCVE 的快）+ 端点迁移（Lexmark 的量）+ 冷门筛选（大厂全重复的教训）。
> 触发：说「cnvd / 挖cnvd」；退出：说「恢复 / 退出cnvd」。
> **2.3 三大特性**：① **无产出不停**（唯一停机=可提交级洞落盘，§0.3/§1.5/§7）② **厂商资质门槛**（注册资本实缴 >5000 万 + 优先国内，§1.1a）③ **复现反虚构规范**（curl 优先 / 真实数据包，§1.4a）。
> 历史教训：深挖单厂商模式（3-5 天）已被实战推翻——单固件深挖 3 小时才两洞，且大厂必撞重复。

## 0. 三原则（全部来自实战教训）

1. **只打中危+能力点**（产证铁律）：判据 = 未授权能拿到什么，不是页面能不能打开。状态页/欢迎页/版本号 = 低危不投入。
2. **冷门优先**：大厂 = 重复重灾区（Lexmark 三报告全被 CNVD-2021-45229/45228/75312 驳回）。§3 黑名单 + 查重前移，只挑「有存量但不被关注」的厂商。
3. **命中≥10 即走**：案例 10 个就是达标线，不放大、不铺量、不截图（用户自复现）。

### 0.3 停机语义：无产出不停（2.3 · 2026-09-13 定）

**唯一合法停机条件 = 已挖到 ≥1 个「可提交级」洞并落盘。**
可提交级 = 命中 ≥10 台 + 查重 no_duplicate + 独立复验 confirmed + **厂商资质达标（§1.1a：注册资本实缴 >5000 万 + 优先国内）** + 报告落盘 `Desktop\cnvd\<厂商>\<日期>\`。
在此之前，**任何"收工"都不成立**——包括：

- 一轮循环没出货 → 换下一条产品线，继续（换线 ≠ 收工）
- 候选池挑剩了 → 回头从原 findings 里换 rule / 换端点 / 换指纹细分再筛（穷尽再穷尽一次）
- 通道额度用尽/限流 → 记断点，恢复后从断点续跑（进度落 progress.md）
- 多条线都 duplicate → §1.1 查重前移加严（条目 >1 就跳），继续找下一条冷门线
- 报告写完 → 那是里程碑不是终点：继续下一条线，**直到用户喊停**（"停/收工/恢复"）

**边界**：本原则只约束"什么时候可以停"。合规红线（§5：只读/间隔/不下载/合法目标）在连续作业下**执行强度不变**，红线优先于本原则——红线冲突时立即停下问用户，不算违反。

## 1. 流程（一产品线一循环，循环至出洞为止）

```
准备(10min) → 厂商资质筛选 → 扫描(脚本) → 查重+抽验(1 agent) → 报告(主对话) → 下一线
```

### 1.1 准备
1. `python cnvd_recon.py --preset <类型>` 拉存量（preset：nvr/printer/industrial/network/access/nas/conference）
2. 指纹聚类（title/server 分组）→ **排除 §3 大厂黑名单** → 挑冷门线（存量 ≥300 的厂商指纹组）
3. **厂商资质核验（2.3 · 证书门槛）**：见 §1.1a —— 这是**发证硬门槛**，不达标的目标哪怕洞成立也白干
4. 按产品线选 §2 端点字典 rules 文件；新线无字典 → 用 rules_generic.json 起步 + 抓 2-3 台设备页面挖接口（≤10 分钟）

### 1.1a 厂商资质筛选（2.3 · 2026-09-13 定 · CNVD 发证门槛）

> **CNVD 证书硬门槛（用户确认）**：① 通用型漏洞 ② **厂商注册资本实缴 > 5000 万元人民币** ③ **优先国内厂商**。
> 甜点区 = **注册资本过 5000 万、但知名度低、非重复重灾区**的中型/小厂。大厂撞重复白干，小厂不够发证资格，**中间层才有证书**。

**逐目标核验（命中 ≥10 后、进报告前必做）**：

| 维度 | 判据 | 不达标处理 |
|------|------|-----------|
| **注册资本实缴** | 国内：企查查/爱企查/天眼查查「注册资本」+「实缴资本」字段，**以实缴为准**（认缴 ≠ 实缴；实缴 ≥5000万 才达标，或看企业规模/年报佐证）；上市/外资：市值/营收折算参考 | <5000万 → **换线**（洞再好也不够发证） |
| **属地** | 优先国内（大陆）；港澳台/境外仅在无国内标的时考虑 | 境外 → 降优先级 |
| **知名度** | WebSearch「厂商名 CNVD/CNNVD/CVE」条目数 + 产品知名度 | 重灾区 → 跳过（§3 黑名单逻辑） |
| **产品形态** | 通用型（同一产品多实例部署）；非一次性项目定制 | 项目定制 → 换线 |

**操作**：
- 国内厂商查工商：WebSearch「<厂商全名> 注册资本 实缴」（企查查/爱企查/天眼查快照多可检索到）
- 外文厂商无"注册资本"概念：查公司形式（上市/营收/员工数）折算判断体量
- **存疑不算过**：查不到实缴就按"未达标"处理，先换线，别赌
- 核验结果记入报告「厂商信息」段（全称/属地/注册资本/实缴/依据来源）

### 1.2 扫描（脚本，主对话不亲手抓包）
1. 资产 CSV → targets.csv（表头 ip,port）
2. `python cnvd_check.py --targets targets.csv --rules rules_xxx.json --geo --out findings.csv`
   - 判据内建：HTTP 双差分（无 cookie 两次可复现）+ match 字段验证；**RTSP 必须 DESCRIBE 200 且 SDP 含 v=0+m=video/audio**，OPTIONS-only 直接丢弃（08-22 返工教训）
3. findings 按 rule_id 聚类：**命中 ≥10 → 进查重；<10 → 换下一线**（不恋战）

### 1.3 查重+抽验（合并成 1 个 agent，一次派发两活）
- 输入：findings.csv 只给 `ip,port,rule_id,url` 四列 + 厂商名（不给 snippet 防预判）
- 输出：`dedup_report.json` + `verify_report.json`
- 检查项（一次性穷举）：
  - **查重四源**：CNVD 官网 / CNNVD / Seebug / WebSearch（site:cnvd.org.cn 厂商名+漏洞点），每条 same(same|similar|different) 判定 + 理由
  - **独立复验 3-5 台**（该洞命中里的随机台）：无 cookie 裸请求复现 / 真实数据非 mock / 蜜罐三判（ip-api 查 geo，云段=yes 优先怀疑）/ 设备自洽
  - 排除必带 fail_reason，禁止"没发现"式结论
- 裁决：`duplicate → 换点或换线`；`no_duplicate + 复验 confirmed → 进报告`
- 红线：只读 GET/OPTIONS/DESCRIBE；单 IP 间隔 ≥1s；不下载敏感文件

### 1.4 报告（主对话）
- 每洞两版：提交版 + 复现版，命名 `<目标>-<日期>-<等级>-<漏洞名>[-提交版|-复现版].md`（hark 命名格式），**固定落 `C:\Users\Administrator\Desktop\cnvd\<厂商>\<日期>\`**（用户 2026-08-22 定，覆盖旧企业src 路径）
- 案例 IP 全量导 `全部案例IP.txt` 同目录（分层：批量命中 / 抽验确认 / confirmed）
- **厂商信息段（2.3 必填）**：报告头表格加「厂商全称 / 属地 / 注册资本(实缴) / 依据来源」——CNVD 审核看厂商资质，缺此段=白干
- **可提交级判定**（2.3 明文化）：命中 ≥10 台 + 查重 no_duplicate + 独立复验 confirmed + **厂商资质达标(实缴>5000万+国内优先)** + 报告落盘 = 可提交级。四条件缺一不可，缺则回到 §1 继续循环，不算停机
- **定级交用户拍板**（CLAUDE.md 铁律），不擅自定义
- 报告写「与历史漏洞差异」段（型号/路径/参数差异点，应对未公开重复）
- **复现步骤遵循 §1.4a 复现规范（2.3 反虚构铁律）**
- 截图：默认不做，用户自己复现看

### 1.4a 复现规范（2.3 · 2026-09-13 定 · 反虚构铁律）

**复现步骤以最简单形式呈现，按优先级选择：**

1. **首选：curl 一行命令 / 浏览器直接访问** —— 凡是能直接做到的（GET 请求、公开端点、无需特殊头部），**必须**用这种形式。目标是读者复制粘贴即可复现。
2. **保底：真实数据包（raw HTTP request/response）贴入** —— curl 无法直接表达时（特殊头部、POST body、二进制、WebSocket 帧、私有协议等），贴**真实请求包**。
3. **铁律一：数据包必须真实** —— 所有贴出的请求/响应包，必须是实操中**真实发送/收到的原文**。**禁止任何虚构、补全、美化、想象**；不得凭记忆"重构"数据包，必须回放你实际跑过的。
4. **铁律二：所有复现方式必须你亲自跑过且能复现** —— 报告里每一步都要能被重复执行得到相同结果；**没跑过的步骤不写进报告**。
5. **铁律三：生成报告时自查** —— 每个请求包/响应片段都能对应到本次实操记录；无法对应的一律删除或重跑后再写。

**报告自查清单（落盘前逐项过）**：
- [ ] 每个 curl 命令/数据包 = 本次真实执行过的（不是凭经验写的"应该是这样"）
- [ ] 响应片段 = 真实收到的原文（截断可以，改写不行）
- [ ] 复现步骤从零可跑通（URL/参数/头部与实测一致）
- [ ] 无任何"示例"、"假设"、"正常情况下会返回"式的虚构内容

### 1.5 循环（无产出不停 · 2.3）
一条线走完 → 分出两种结果：
- **出货**（报告落盘）→ 归档 → 继续下一条线（里程碑，不是终点）
- **没出货**（命中 <10 / 全 duplicate / 无端点可打）→ 换下一条线继续，**不许以"今晚够数了/没线了"收工**

理论停机只有三种：① 已出货且用户喊停 ② 用户喊停 ③ 撞 §5 红线需用户裁决。
诚实条款：若连续多轮确实挖不到可提交洞，**不许谎报出货**（把 review/mock 项包装成 confirmed 提交 = 事故）；正确做法是如实报「已穷尽 N 条线未出洞 + 剩下的可行方向」，再由用户决定加范围还是停。

**长跑辅助**（连续作业下的进度与留痕）：
- 进度/断点落 `progress.md`（防上下文压缩丢失）；每个候选线一行看板（§6）
- 每出一条线的小结写 `Desktop\cnvd\进度台账.md`（候选线/结果/断点），跨天续跑不迷路
- 长跑期间保持 §5 红线执行强度不变；会话被压缩后先读 progress.md 续跑
