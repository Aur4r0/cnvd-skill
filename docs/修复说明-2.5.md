## 修复 1：扫描异常被静默吞掉

### 现象

`work()` 里任何未捕获异常都会让该目标**从结果里彻底消失**：不进 findings、不进台账、进度计数器照常递增，命令行输出也看不到任何异常。整轮跑完看起来"全部完成"，实际有目标被跳过。

### 根因

```python
with ThreadPoolExecutor(max_workers=args.workers) as ex:
    ex.map(work, targets)          # 返回值未迭代
```

`Executor.map()` 的默认 `chunksize` 行为下，异常存放在返回的迭代器里；**不迭代返回值 = 异常被丢弃**。验证：

```console
$ python3 -c "
from concurrent.futures import ThreadPoolExecutor
def boom(x):
    if x == 2: raise ValueError('kaboom')
    print(f'  ok {x}')
with ThreadPoolExecutor(max_workers=2) as ex:
    ex.map(boom, [1,2,3])
print('主流程正常结束 —— 异常被完全吞掉')"
  ok 1
  ok 3
主流程正常结束 —— 异常被完全吞掉
```

注意 `ok 2` 缺失但无任何错误提示。

### 修复

- 拆分 `work()`（负责落盘与计数）与 `scan_target()`（纯扫描逻辑）。`work()` 用 try/except 收敛所有异常
- 失败目标：**不写入「已完成」**，台账 `note` 列记 `ERROR <类型>: <消息>`，结尾打印失败汇总
- `--resume` 跳过判定排除 `note` 以 `ERROR` 开头的行 —— 失败目标会重试，不会被当成已完成
- `list(ex.map(...))` 消费迭代器，作为兜底（`work` 已自捕获，此处防 `work` 本身出错）

### 验证

注入探针异常后：

```
    失败 1/2 127.0.0.1:18080 ERROR RuntimeError: 模拟探针崩溃
    失败 2/2 192.0.2.99:80 ERROR RuntimeError: 模拟探针崩溃
== 注意: 2 个目标扫描异常, 已记台账 note 列, --resume 会重试 ==
    ✗ 127.0.0.1:18080 ERROR RuntimeError: 模拟探针崩溃
```

台账：

```csv
ip,port,hits,scanned_at,note
127.0.0.1,18080,0,2026-11-16 10:15:17,ERROR RuntimeError: 模拟探针崩溃
```

`--resume` 确认会重试：`== 断点续跑: 已完成 0 个目标, 剩余 2 个待扫 ==`。

## 修复 2：`exclude_any` 数字状态码误杀真命中

### 现象

响应体里出现 `401`、`404` 这类数字串的**真命中会被丢弃**。例如返回 `{"password":"admin123","serial":"SN4012233"}` 的配置泄露，因 body 含 `SN4012233` 中含 `401` 而判为"未命中"。

### 根因

`evaluate_http()` 对 `exclude_any` 做纯子串匹配：

```python
for x in rule.get("exclude_any", []):
    if x.lower() in b:      # "401" in "sn4012233" → True
        return None
```

而 21 条规则里有 15 条把 `401`/`403`/`404` 写进了 `exclude_any`。这些本意是「排除认证失败页」，但子串匹配不区分语义。

### 修复

纯 3 位数字视为 HTTP 状态码，**只在状态层面生效，不参与 body 子串匹配**：

```python
EXCLUDE_CODE_RE = re.compile(r"^\d{3}$")
...
for x in rule.get("exclude_any", []):
    if EXCLUDE_CODE_RE.match(x.strip()):
        continue            # 数字码不参与 body 匹配
    if x.lower() in b:
        return None
```

状态码排除本就由 `if status >= 400: return None` 覆盖，删除 body 层的数字匹配不损失防护。字符串型排除（`login`/`unauthorized`/`forbidden`）保持不变。

### 验证

| 响应体 | 修复前 | 修复后 |
|--------|--------|--------|
| `{"password":"admin123","serial":"SN4012233"}` | 丢弃 ✗ | 命中 ✓ |
| `{"password":"admin123"}` | 命中 | 命中 |
| `please login to continue` | 丢弃 | 丢弃 ✓ |
| HTTP 401 状态 | 丢弃 | 丢弃 ✓ |
| body 含 `unauthorized` 单词 | 丢弃 | 丢弃 ✓ |

## 修复 3：抽验与主扫的 RTSP 判据不一致

### 现象

主扫 `cnvd_check.py` 要求 `v=0` + `m=video/audio`；抽验 `verify_rtsp2.py` 的 `has_sdp()` 却多一个宽松分支：

```python
if "m=video" in t and "a=control" in t:
    return True             # 无需 v=0
```

后果：抽验可能 confirm 一个主扫描根本不认的命中，两套判据打架。

### 修复

`verify_rtsp2.py` 的 `has_sdp()` 对齐主扫判据，删除宽松分支。

### 附带：主扫 `recv_all` 的截断风险

原实现读到第一个 `CRLFCRLF` 且长度 >200 就停止收包。若 SDP 正文跨多个 TCP 段，`v=0` / `m=video` 可能落在未收完的部分，造成**假阴性**。改为解析 `Content-Length` 并收满 body。

### 验证

| 响应 | 结果 |
|------|------|
| 真 SDP（`v=0` + `m=video`） | True ✓ |
| `m=video` + `a=control` 但无 `v=0` | False ✓（旧代码 True） |
| 仅 OPTIONS 200 | False ✓ |
| `v=0` 但无媒体行 | False ✓ |
| 400 字节 SDP 跨段 | 正确收满并命中 ✓ |

## 修复 4：targets.csv 脏数据

### 现象

- 空 IP 被当目标扫描，产生 `:80` 这种无效目标
- `r["ip"]` 为 `None`（某些畸形 CSV）会抛 `AttributeError`，不在原捕获范围 `(KeyError, ValueError)` 内

### 修复

新增 `valid_host()`（IPv4/IPv6 字面量或合法主机名）与端口范围校验；`load_targets()` 返回 `(targets, skipped)`，跳过行带行号与原因，主流程打印前 5 条。目标全被跳过时直接报错退出（exit 1），不再空跑。

特别处理：形如 IPv4 的点分数字串若 `ip_address()` 解析失败（如 `192.168.1.256`），**拒绝而非降级为主机名**。

### 验证

```console
$ python cnvd_check.py --targets dirty.csv ...
== 输入提示: 3 行被跳过（空 IP / 端口非法 / 端口越界）==
    - 第2行: IP 非法 ('')
    - 第4行: 端口非法 ('abc')
    - 第5行: 端口越界 (99999)
```

主机名校验覆盖：`example.com` / `sub.example.co.uk` / `::1` / `2001:db8::1` / `host-1` 通过；空值 / 含空格 / `::::` / `-bad.com` / 超长 / `192.168.1.256` / `999.999.999.999` 拒绝。

## 修复 5：`utcfromtimestamp` 弃用

`verify_newfe_A.py` 用 `datetime.datetime.utcfromtimestamp()`，在 Python 3.12+ 触发 `DeprecationWarning`，计划移除。

改为 `datetime.fromtimestamp(t, datetime.timezone.utc)`（`timezone.utc` 自 3.2 可用，保持 3.8+ 兼容）。已验证所有脚本在 3.14 下导入无弃用告警。

## 未纳入本版

以下为走查中发现但**未修**的项，记录原因：

- **`cnvd_recon.py` 的 `quote(q_enc)` 未传 `safe=''`**：base64 中的 `/` 不被编码。部分中转站可能解析出错，但缺少可复现的受影响通道样本，改后可能反而不兼容现有中转站。
- **`bing_search.py` 依赖 Bing 页面结构**：页面改版即失效。作为查重辅助够用，加固收益低于维护成本。
- **抽验脚本各自的节流实现**：`verify_*.py` 各自用 `time.sleep` 而非共用 Pacer。均为单线程串行，行为正确，重构收益低。

**未改动**：端点字典规则内容与判据语义、SKILL.md 方法论与合规红线、`cnvd_recon.py` 的通道逻辑。
