## 修复 1：`verify_rtsp2.py` 每次运行必崩（高）

### 现象

```console
$ python verify_rtsp2.py --csv verify_input.csv --out out.json
total cases: 1
[1/1] 127.0.0.1:554 ...
Traceback (most recent call last):
  File "verify_rtsp2.py", line 220, in main
    "case_id": c["case_id"].strip(),
KeyError: 'case_id'
```

探针本身跑完了（`check_one` 成功返回），但写结果时崩掉，**整个报告丢失**。

### 根因

`c` 是输入 CSV 的一行。按文档规定，抽验输入只有四列 `ip,port,rule_id,url`，**没有 `case_id` 这一列**。代码却直接读 `c["case_id"]`。

这是上游 v2.0 就存在的缺陷，此前几轮审查（包括我自己前两轮）都只做静态阅读，没有实际跑过这个脚本，所以一直没暴露。

### 修复

```python
"case_id": f"{ip}_{port}_{(c.get('rule_id') or '').strip()}",
```

用已有的列拼接，与本文件其余 `case_id` 的构造方式一致。

### 验证

修复后同一命令正常产出：`DONE, written vout.json`，`case_id=127.0.0.1_554_rtsp-unauth`。

## 修复 2：抽验脚本遇空字段即崩

### 现象

CSV 里的空字段被 `csv.DictReader` 读成 `None`，而代码统一写 `c["ip"].strip()`：

```python
ip = c["ip"].strip()        # None.strip() → AttributeError
```

抽验输入常由人工整理（文档要求"只给四列"），有空行或漏填很正常。一个空字段就让整个抽验中断。

`verify_rtsp2.py` 还有第二处：`url.split("://", 1)[1]` 在 URL 缺 scheme 时 `IndexError`。

### 修复

四个脚本（`verify_newfe_A` / `verify_newfe_B` / `verify_rtsp2` / `probe_newfe_A_bodies`）统一改为安全读取：

```python
ip = (c.get("ip") or "").strip()
```

并对空 `url`/`ip`、缺 scheme、端口非法的行打印跳过原因后继续，不再中断整轮。

### 验证

含一空行 + 一条有效记录的 CSV：

```
[1/2] 跳过: url/ip 为空
[2/2] 127.0.0.1_554_rtsp-unauth ...
```

四个脚本均正常跑完。

## 修复 3：`exclude_any` 字符串排除词误杀真命中（高）

### 现象

响应体里含 `login_time` / `last_login` / `loginCount` 这类字段的**真命中会被丢弃**。设备配置 JSON 里这些字段极常见，而 21 条规则里有 13 条把 `login` 写进了 `exclude_any`。

```console
含 login 子串的合法配置字段（都被误杀）:
  丢弃 ✗ login_time      丢弃 ✗ last_login
  丢弃 ✗ loginCount      丢弃 ✗ loginUser
  丢弃 ✗ loginStatus     丢弃 ✗ loginAttempts
```

### 根因

2.4 只修了数字状态码（`401` 误杀 `SN4012233`），字符串排除词仍是纯子串匹配。同类问题，换了个形状。

### 修复

按排除词的形态分两种匹配策略：

| 排除词形态 | 策略 | 例 |
|---|---|---|
| 纯 ASCII 单词（`^[A-Za-z][A-Za-z0-9]*$`） | 词边界 `\bword\b` | `login` `unauthorized` `forbidden` `sender` |
| 含中文 / 以符号开头结尾 / 含空格 | 裸子串 | `登入畫面` `<html` `function(` `not found` |

词边界下 `login` 不再匹配 `login_time`（`_` 是单词字符，边界不成立），但仍匹配 `please login` 和 `login.html`（`.` 是边界）。

**为什么不用统一词边界**：`\b` 在中文之间不成立（`登入畫面` 会漏判），`<html` 以 `<` 开头也没有前导边界。统一用 `\b` 会把这些真正的排除特征变成失效——那是从漏报翻成误报，同样有害。

### 验证

14 项边界用例全通过：

```
✓ login  in {"login_time":"y"}           -> 不排除（真命中保留）
✓ login  in "please login to continue"   -> 排除
✓ login  in "login.html"                 -> 排除
✓ 登入畫面 in "請先登入畫面再繼續"          -> 排除
✓ <html   in "<html><body>"              -> 排除
✓ sender  in "s:Sender"（ONVIF 错误）     -> 排除
✓ sender  in 正常 GetDeviceInformation   -> 不排除
```

## 修复 4：并发写入的三处数据一致性问题

### 4a. 中断导致 findings 重复

`append_findings` 与 `write_ledger` 是两次独立追加写。进程若在两次之间被杀，台账没有该目标记录，`--resume` 重扫时会再追加一遍，最终重写不去重 → 命中重复累积。

**修复**：最终重写按 `(ip, port, rule_id, url)` 去重。验证：3 条重复 → 1 条。

### 4b. 输入重复行导致重复扫描

`load_targets` 不去重。CSV 里重复的 `ip:port` 会被并发扫两遍，findings 和台账各多写一份。

**修复**：加载时按 `(ip, port)` 去重，重复行记入跳过列表并报行号。

```console
== 输入提示: 2 行被跳过 ==
    - 第3行: 重复目标 (127.0.0.1:18080)
```

### 4c. 写盘失败炸掉整轮

扫描的 `append_findings` / `write_ledger` 在 `work()` 的 try 范围**之外**。磁盘满或权限不足时 `OSError` 会经 `ex.map` 抛出，中止整轮并跳过最终导出。

**修复**：
- 写盘移入 try，`OSError` 时记该目标失败（不写「已完成」，续跑重试）
- 台账写入单独兜底，失败记入 `io_errors` 并在结尾显著提示
- 最终重写 findings 也包 try，失败如实告知（增量结果仍在磁盘上）

## 修复 5：畸形 `Content-Length` 可撑爆内存

2.5 为修 RTSP 假阴性改成按 `Content-Length` 收满 body。风险：服务端声称 `Content-Length: 104857600` 时会一直读到超时。

**修复**：总量上限 `RECV_MAX_BYTES = 65536`（SDP 远小于此）。

**验证**：服务端声称 100MB 实际只发几十字节 → 3.6s 完成（timeout 兜底），且正确命中。

## 修复 6：抽验脚本 OPTIONS 不受节流（合规）

### 现象

`verify_newfe_B.py` 与 `verify_rtsp2.py` 里，`OPTIONS` 是发在节流函数之前（或完全不经过它）。后果：OPTIONS → 第一条 DESCRIBE 之间 **0 间隔**；同 IP 有多个 RTSP case 时 OPTIONS 也完全不受控。`rtsp_probe.py` 更彻底——整个脚本没有任何 sleep，单目标最多连发 10 个请求。

### 修复

- `verify_newfe_B.py`：`check_rtsp()` 首行加 `rtsp_gap()`，OPTIONS 走节流
- `verify_rtsp2.py`：`time.sleep(1.0)` 从每轮末尾移到请求之前，OPTIONS 后的第一条 DESCRIBE 也有间隔
- `rtsp_probe.py`：新增 `INTERVAL = 1.0`，路径循环之间、以及 `desc()` 内 OPTIONS→DESCRIBE 之间都加间隔；`int(port)` 加校验

## 修复 7：`real_data` 判据字段从不赋值

### 现象

`verify_newfe_A.py` 里 `real_ok` 变量算出来了，但只用于决定 `verdict`，**从未写回 `rec["checks"]["real_data"]`**。结果：所有 `confirmed` 的 case 报告里 `real_data: false`，与实际结论自相矛盾，会误导人工复核。

### 修复

`rec["checks"]["real_data"] = bool(real_ok)`。

同时清掉一个误导性变量：`headers_note = ""` 恒为空（因为 `http_get()` 根本不返回响应头），却一路传给 `infer_model()`。现在显式传 `""` 并注明原因。

## 修复 8：`match_any` 泛词导致大面积误报（高）

### 现象

规则字典里多条 `match_any` 含 `uid` / `channel` / `user` / `role` / `file` 这类普通页面也有的词。因为判据是"命中任一即可"，**只要能匹配上最宽的那个词就算命中**：

```console
任何含 uuid 的 JS 页面           -> 命中
普通页含 "channel"              -> 命中
普通说明页含 "role"             -> 命中（误报）
真 Config.json                  -> 命中
```

### 根因

`match_any` 的设计是"任一命中"，没有"至少命中 N 个"的概念。同一条规则里混入精确特征（`zwp2p`）和泛词（`uid`）时，精度被泛词拉平。

### 修复

新增可选字段 `min_hits`（默认 `1`，保持向后兼容），要求命中多个特征词才判定：

```json
{
  "match_any": ["zwp2p", "uid", "devicetype", "channel"],
  "min_hits": 2
}
```

对 9 条泛词规则设 `min_hits: 2`：`config-json`、`config-uid`、`ews-vnc-panel`、`ews-users-mgmt`、`ews-firmware-update`、`ews-backup-pwd`、`conf-read`、`api-sensitive`、`userlist`。

精确指纹规则（`drid.com.tw`、`act_id_1`、`SuperPasswordQRCode` 等）保持默认 1。

### 验证

| 响应 | 修复前 | 修复后 |
|------|--------|--------|
| 含 `uuid` 的普通 JS 页 | 命中 ✗ | 丢弃 ✓ |
| 普通页含 `channel` | 命中 ✗ | 丢弃 ✓ |
| 真 Config.json（四特征齐全） | 命中 | 命中 ✓ |

规则编写指南已补 `min_hits` 与 `exclude_any` 匹配方式的说明。

## 方法说明

本轮与前两轮的区别：**每条修复都先用本地 mock 服务复现，修复后再验证**，而不是只读代码判断。`verify_rtsp2.py` 的必崩 bug 正是这样发现的——静态阅读了三轮都没看出来，实际跑一次就崩。

规则层的问题（修复 8）与前七条性质不同：前七条是**代码缺陷**，第八条是**判据设计缺陷**——代码完全按规则正确执行，问题在于规则本身太宽松。这类问题静态审查代码看不出来，必须拿真实响应去试。

未纳入本版的项沿用 [2.5 的遗留清单](修复说明-2.5.md#未纳入本版)。
