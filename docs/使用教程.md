# 使用教程 —— 从零跑通一条产品线

> 本文以「NVR 产品线（Boa 固件）」为例，完整走一遍 测绘 → 验证 → 抽验 → 报告 的全流程。
> 换其他产品线时把 preset / rules 换成对应文件即可，流程不变。

---

## 0. 准备工作（10 分钟）

### 0.1 环境

```bat
python --version        :: 应输出 Python 3.8+（推荐 3.12）
```

无输出 → 先装 Python（见主 README「快速开始」）。

### 0.2 配置 FOFA 通道

编辑包根目录 `api_keys.json`，把 `channels` 数组里第一个通道的 `base_url` / `key` 换成你自己的：

```json
{
  "channels": [
    {
      "name": "primary",
      "enabled": true,
      "base_url": "https://你的中转站",
      "search_path": "/api/v1/search/all",
      "key_param": "key",
      "query_param": "qbase64",
      "key": "你的key"
    }
  ]
}
```

验证配置是否可用：

```bat
cd tools\scripts
python cnvd_recon.py --list-channels     :: 列出已启用的通道
```

### 0.3 冒烟自检

```bat
cd 包根目录
校验.bat
```

全 ✅（key 未填时 4b 显示 TODO 属正常）即可开工。

## 1. 阶段 0：测绘（拉存量）

### 1.1 挑产品线

```bat
python cnvd_recon.py --list-presets
```

内置 7 条产品线：

| preset | 产品线 |
|--------|--------|
| `nvr` | 视频监控 NVR/DVR/IPC |
| `printer` | 打印机/复印机/MFP |
| `industrial` | 工控 HMI/PLC/SCADA |
| `network` | 网络设备 路由器/交换机/AC |
| `access` | 门禁/考勤/闸机 |
| `nas` | NAS/存储 |
| `conference` | 会议终端/视频会议 |

### 1.2 拉取存量

```bat
python cnvd_recon.py --preset nvr --out stage0_nvr.csv
```

输出 `stage0_nvr.csv`，字段：`ip,port,host,title,server`。

自定义查询（可多条）：

```bat
python cnvd_recon.py --query 'title="NVR" && port="8080"' --query 'title="网络摄像机"' --out stage0_custom.csv
```

### 1.3 筛查（关键步骤）

对 `stage0_nvr.csv` 做**指纹聚类**（按 title/server 分组），然后：

1. **排除大厂黑名单**（SKILL.md §3）——海康/大华/宇视/雄迈/天地伟业等大厂是 CNVD 重复重灾区，直接跳过
2. **挑冷门**：优先「有存量（≥300 台）但不被关注」的厂商指纹组——白牌固件线（Boa/webs 系）、区域小厂、贴牌 OEM
3. **查重前移**：对候选厂商名做一次 WebSearch「厂商名 CNVD 未授权」，**条目 >2 的直接跳过**，避免白干

```bat
:: 查重辅助（内置了常用查询集，改脚本头部 queries 可自定义）
python bing_search.py
```

### 1.4 整理 targets.csv

从挑选出的资产整理出 check 的输入文件，**表头必须是 `ip,port` 两列**：

```csv
ip,port
192.0.2.10,80
192.0.2.11,8080
```

> 格式参考：`示例产出\targets_样例-脱敏.csv`

## 2. 阶段 1：批量验证（脚本干，不亲手抓包）

### 2.1 选规则字典

| 产品线 | 规则文件 |
|--------|----------|
| NVR（Boa 固件） | `tools\rules\rules_boa.json` |
| 新前端 NVR/IPC | `tools\rules\rules_newfe.json` |
| 门禁 | `rules_access_menjin.json` / `rules_access_drid.json` / `rules_access_secom.json` |
| EWS 打印机 | `rules_ews_printer.json` |
| 新线无字典 | `rules_generic.json` 起步 |

### 2.2 跑批量验证

```bat
python cnvd_check.py --targets targets.csv --rules ..\rules\rules_boa.json --geo --out findings.csv
```

参数说明：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--targets` | 必填 | 资产 CSV（`ip,port`） |
| `--rules` | 必填 | 规则 JSON |
| `--geo` | 关 | 查 ip-api 归属 + 云厂商标记（慢，建议开） |
| `--interval` | 1.0 | **同 IP 请求间隔秒——合规红线，不要调低** |
| `--workers` | 10 | 跨 IP 并发数 |
| `--resume` | 关 | 断点续跑：跳过 `--out` 文件里已完成的目标 |
| `--out` | findings.csv | 输出路径 |

### 2.3 看结果

`findings.csv` 每行一个命中，关键列：

- `severity`：high / mid / low / review
- `mock`：True = 命中特征是占位/伪造提示（防误报机制），需人工复核
- `cloud_suspect`：yes = 目标 IP 属云厂商段（可能是蜜罐/研究环境），需人工复核
- `snippet`：命中上下文（抽验环节不给 agent 看这列，防预判）

### 2.4 聚类裁决

按 `rule_id` 聚类统计命中数：

- **≥10 台 → 进查重+抽验**（够一个通用型漏洞的案例量）
- **<10 台 → 换下一条线，不恋战**

---

## 3. 阶段 1.5：查重 + 抽验（派 agent 干）

把 findings 整理成**四列**（`ip,port,rule_id,url`）作为抽验输入（格式见 `示例产出\verify_prompt_template.md`），派发一个独立 agent，一次干两活：

### 3.1 查重（四源穷举）

- CNVD 官网（site:cnvd.org.cn 厂商名+漏洞点）
- CNNVD
- Seebug
- WebSearch

每条给 `same | similar | different` 判定 + 理由。

### 3.2 独立复验（随机 3-5 台）

- 无 cookie 裸请求复现（证明未授权）
- 真实数据判定（非 mock / 非空壳）
- 蜜罐三判（ip-api 查 geo，云段优先怀疑；设备自洽加分）
- 排除必须带 `fail_reason` 证据，**禁止"没发现"式结论**

### 3.3 裁决

```
duplicate              → 换点或换线
no_duplicate + 复验通过 → 进报告
```

抽验脚本（新前端线专项）：

```bat
python verify_newfe_A.py --csv verify_input.csv --out verify_report_A.json
python verify_newfe_B.py --csv verify_input.csv --out verify_report_B.json
python verify_rtsp2.py   --csv verify_input.csv --out verify_report_rtsp2.json
```

RTSP 单点深挖（想手动确认某台时用）：

```bat
python rtsp_probe.py 192.0.2.10:554
python rtsp_live_verify.py 192.0.2.10:554     :: 真拉流四步：DESCRIBE→SETUP→PLAY→RTP 计数
```

---

## 4. 阶段 2：写报告

按 SKILL.md §1.4：

1. **每洞两版**：提交版 + 复现版
2. **命名**：`<目标>-<日期>-<等级>-<漏洞名>[-提交版|-复现版].md`
3. **产出位置**：`Desktop\cnvd\<厂商>\<日期>\`（Linux/macOS 对照本机桌面路径）
4. **案例 IP 全量导出** `全部案例IP.txt` 同目录（分层：批量命中 / 抽验确认 / confirmed）
5. **定级交用户拍板**，不擅自定义
6. 报告写「与历史漏洞差异」段（型号/路径/参数差异点，应对未公开重复）
7. 截图默认不做，用户自己复现看

---

## 5. 循环

一条线完成（报告落盘）→ 归档 → 下一条线。

**每晚目标：2-3 条线 / 3-5 洞。**

## 附：常见停顿点

| 症状 | 处理 |
|------|------|
| recon 报"所有通道均失败" | key 没填（预期）→ 填 key；已填 → 检查 base_url/search_path/query_param 三项 |
| check 跑很慢 | 正常。单 IP ≥1s 是红线；100 台约 10-15 分钟 |
| findings 一堆 mock/cloud_suspect | 正常，防误报机制在工作，抽验时人工/agent 复核 |
| 抽验脚本说"未知 rule_id" | 该脚本只认自己支持的 rule_id（如 superpw-qr / config-uid），检查输入 CSV |
| 中文乱码 | 命令行先执行 `chcp 65001` |
